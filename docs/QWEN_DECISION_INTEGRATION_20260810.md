# Qwen 接入上海进近决策链路与受限混合评估

日期：2026-08-10

## 1. 结论

已经把本地 Qwen 接入“基础触发器和候选生成 → Qwen Top-K 候选重排 → 运行约束 → 有限时域安全验证 → 指令输出”的现有离线回放链路，并完成 2025-07-02 全日 21,600 tick 评估。

本轮是**受限混合实验**：最多调用 Qwen 20 次，其余决策使用原 v1.2 基线。20 次调用全部成功且输出均为候选集合内的合法 ID，但 Qwen 20 次均未改变基础模型首选候选，因此最终 784 条系统指令和全部模仿指标与 v1.2 基线完全一致。本轮证明了接入、约束、回退和审计链路可运行，但没有证明 Qwen 能提高上海进近管制员指令模仿精度。

## 2. 决策链路

1. 读取冻结航迹、飞行计划、SID/STAR、许可高度、历史许可和交通关系；
2. v1.2 模型计算 HOLD 与非 HOLD 候选分数，并判断是否触发指令；
3. 仅当触发且前两名候选分差不超过 0.08 时，向 Qwen 提交 Top-5 候选；
4. Qwen 只能返回给定 `candidate_id`，不能生成任意高度、速度或 BlueSky 命令；
5. 非法输出、超时或服务错误自动回退到基础排序；
6. Qwen 首选候选仍须通过冷却、重复目标、方向约束和五分钟简化安全验证；
7. 日志记录模型身份、调用次数、响应延迟、改选次数和失败类型。

## 3. 已验证环境与可移植配置

- 显卡：NVIDIA GeForce GTX 1070 Ti，8 GB；
- 已验证依赖版本见 `evaluation_platform/requirements-qwen-reranker.txt`；
- 本地模型通过 `--model` 参数提供，不在代码或配置中写死个人路径；
- tokenizer：来自同基座 `Qwen3-4B-Instruct-2507`；
- 部署方式：FP32、GPU/CPU 自动分层；
- Qwen服务默认地址：`http://127.0.0.1:8766`，与评估平台的8765端口分离。

基座目录 `Qwen3-4B-Instruct-2507` 在 4 bit、8 bit、FP16 分层和简单英文提示下均出现无意义输出，不能用于正式计算。合并后的冲突模型通过简单问答和候选 ID 约束测试，因此本轮只使用合并模型。该模型原训练任务是冲突解脱，不是上海进近程序调配，存在明确的任务域不匹配。

## 6. 结果解释

汇总文件记录了 20 次成功调用；旧版逐时刻日志因 `aircraft_audit_top` 只保留前 5 架航空器，只能直接展开其中 19 次。这 19 次均集中在基础模型首选 `ALT_6000` 的不确定候选组，Qwen继续选择 `ALT_6000`。代码现已新增独立的 `qwen_decisions` 字段，后续回放不会再受前 5 条审计截断影响。可能原因包括：

1. 当前可运行模型是冲突解脱微调模型，不具备专门的上海进近程序和许可调配训练；
2. Qwen输入中保留基础候选分数，模型可能把基础排序当作强先验；
3. 20 次受限调用覆盖率低，且未做按飞行阶段、候选族和时间段分层抽样；
4. 当前基础触发器仍然不生成速度指令，Qwen只做触发后的候选重排，不能修复速度触发缺失。

因此，本结果只能说明“Qwen受约束重排链路可运行且没有破坏基线”，不能说明Qwen改善了模仿精度。

## 7. 后续进入有效实验的条件

1. 重新校验或重新同步可用的 `Qwen3-4B-Instruct-2507` 基座权重；
2. 用 compact v7 正例和同 schema 的 NOOP/HOLD 状态训练上海进近 LoRA；
3. 将训练目标限定为 `ISSUE/HOLD/ABSTAIN + candidate_id`，不自由生成数值；
4. 按到达/离场、ALT/SPD、时间段和基础候选分差做分层 Qwen 调用；
5. 在可用大显存服务器上扩大到全量调用，并继续保留合法候选校验、安全验证和自动回退；
6. 只有当严格参数宏召回或速度召回提升，同时系统精度和指令膨胀率不恶化时，才允许替换默认基线。
